<known_gap>
## Known Limitation: AUTO_MODE_CHECKLIST

`src/prompt-transform.ts` contains `AUTO_MODE_CHECKLIST` (~line 923) which injects a string into generated prompts that includes `gsd_query({command: "init.plan-phase", args: ["\${PHASE}"]})`. This is deliberately left untouched at Phase 8 close because Phase 9 (RUNTIME-03) removes `AUTO_MODE_CHECKLIST` entirely. Modifying it in Phase 8 only to delete it in Phase 9 would be wasted churn.

**Side effect:** `--chain` / `--auto` invocations between Phase 8 close and Phase 9 ship will surface a missing Pi tool error if they hit the AUTO_MODE_CHECKLIST path. This is a transient gap with a committed fix already scheduled.

**UPSTREAM-03 Phase 8 scope:** Pi-tool retirement + launcher transform. The prompt-injection side (AUTO_MODE_CHECKLIST → gsd_run) completes in Phase 9 alongside AUTO_MODE_CHECKLIST deletion.

## Wave-swap rationale and residual-test deletion

Phase 8 runs 08-03 (bridge retirement) in wave 2 BEFORE 08-02 (package upgrade) in wave 3, to keep `npm run check` green at every commit tip per D-40. The original "delete + upgrade" order would have left `src/gsd-query-tool.ts` referencing a removed upstream SDK path at 08-02 tip — confirmed by plan-checker goal-backward verification.

The deleted `$GSD_SDK` residual e2e test (in `tests/e2e/workflow-fidelity.test.ts`) is intentional: with the transform pipeline no longer rewriting `$GSD_SDK`, the residual count is undefined for any 1.1.0 source workflow and the assertion would always fail. Upstream 1.2.0 (installed in 08-02) drops `$GSD_SDK` from source workflows entirely, so the residual concept is obsolete post-Phase 8.
</known_gap>
