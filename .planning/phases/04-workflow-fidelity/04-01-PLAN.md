  <action>Implement AskUserQuestion-to-ask_user_question transformation per D-01 and D-04. All transformations are pure string functions with no filesystem access, following the pattern of normalizeGsdSlashReferences.

Key design decisions:
- Add a new exported function `transformAskUserQuestionForPi(input: string): string` to src/prompt-transform.ts
- The function must parse GSD's AskUserQuestion calling patterns and emit rpiv-compatible ask_user_question schema
- GSD patterns found in upstream workflows include:
  - `AskUserQuestion("header", "question", ["A", "B"])` — flat string options → `{ label: "A", description: "A" }` (where description defaults to same as label)
  - `AskUserQuestion("header", "question", [{label: "A", description: "desc A"}, {label: "B", description: "desc B"}])` — object options with label+description
  - `AskUserQuestion({ header: "...", question: "...", options: [...], multiSelect: true/false })` — already partially structured
  - Multi-line calls where options span multiple lines
- The rpiv schema target is: `ask_user_question({ questions: [{ question: string, header: string (max 16 chars), options: [{ label: string (1-5 words), description: string }], multiSelect?: boolean }] })`
- Use regex with careful balancing for nested brackets. Consider a two-pass approach: first identify AskUserQuestion call boundaries, then parse arguments.
- Must NOT transform AskUserQuestion inside markdown code fences (```...```) — these are example/documentation text that should be preserved as-is.
- Must NOT transform text that already contains ask_user_question (idempotency guard).
- Call `transformAskUserQuestionForPi` from `generatePrompts` in src/generator.ts, after `addPiSubagentGuidance` and `normalizeGsdSlashReferences`.

After implementing, run: `npm test -- --reporter=verbose tests/prompt-transform.test.ts`
  </action>
