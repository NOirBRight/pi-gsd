# Plan 06-01: Fix Workflow Path Rewriting + Pipeline Integration

## Problem

`rewriteWorkflowPaths()` has 15 passing unit tests but produces **zero rewrites** in the actual generation pipeline. The `generated/prompts/` and `generated/workflows/` output still contains `~/.claude/`, `$HOME/.claude/`, and `node_modules/` path references instead of `generated/workflows/` references.

## Root Cause Analysis

Three possible causes (ordered by likelihood):

1. **`splitCodeFences()` is protecting workflow content that shouldn't be protected.** The `<process>` section uses backtick-wrapped paths inside markdown prose, not inside triple-backtick code blocks. But if upstream files use indented code blocks or other fence-like constructs, `splitCodeFences` might incorrectly classify content as "code".

2. **Regex compilation mismatch between TS source and built JS.** The template-literal regex patterns with backtick characters (`[\s'"`]`) may behave differently in the compiled output. Need to verify with integration testing.

3. **The function is called but its output is discarded.** Less likely (verified the call chain), but worth confirming with logging.

## Steps

### Step 1: Add debug logging to `rewriteWorkflowPaths` (TDD red)

- Add a `DEBUG_REWRITE` environment variable check that logs before/after content and match counts
- Run `generate --cwd .` with debug enabled to see what the function actually receives and produces
- Identify which of the 3 root causes is actually responsible

### Step 2: Fix the root cause (TDD green)

- **If cause 1 (code-fence over-protection):** Create a `transformWorkflowContent()` that applies path rewrites BEFORE `splitCodeFences()` for workflow files, or use a different splitting strategy for workflow context
- **If cause 2 (regex mismatch):** Switch from regex to line-by-line string replacement with known path prefixes (`~/.claude/`, `$HOME/.claude/`, `node_modules/@opengsd/`)
- **If cause 3 (output discarded):** Fix the call chain

### Step 3: Integration tests for pipeline output

- Add `tests/generator-pipeline.test.ts` that runs `generateAll()` and asserts:
  - Zero `~/.claude/get-shit-done-redux/` references in generated prompts
  - Zero `$HOME/.claude/get-shit-done-redux/` references in generated prompts
  - Zero `node_modules/@opengsd/get-shit-done-redux/get-shit-done/` path references in `<process>` sections (outside code fences)
  - All those references are replaced with `generated/workflows/` paths
  - Code-fence content is preserved as-is (no modification inside ` ``` ` blocks)

### Step 4: Extend E2E generate smoke test

- Update `tests/e2e/generate-smoke.test.ts` to verify path rewriting in generated output
- Add assertions for `generated/workflows/` directory containing correctly pathed references
