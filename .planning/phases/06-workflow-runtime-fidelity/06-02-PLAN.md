# Plan 06-02: Transform Skill() Inside Workflow Code Fences

## Problem

24 Skill() calls in workflow files are inside ``` code fences. `transformSkillDispatchForPi` uses `splitCodeFences()` to protect code fence content, so these are skipped. In workflow context, code fences contain LLM-executable instructions, not display code.

## Approach

### Strategy: Dual-pass transformation

Instead of removing code-fence protection entirely (which would break command prompts that have genuine display code), add a **second pass** for workflow files that transforms Skill() calls INSIDE code fences.

**Why not just remove code-fence protection for workflows?**
- Some workflow code fences contain bash snippets that should NOT be transformed (e.g., literal `$GSD_SDK` commands that we handle differently)
- We need surgical Skill() replacement, not blanket transformation

### Implementation

1. **New function: `transformWorkflowCodeFences(input: string, packageName: string): string`**
   - Uses `splitCodeFences()` to identify code fence segments
   - For each code fence segment, applies `transformSkillDispatchForPi()` inside
   - Non-code-fence segments are left as-is (already transformed by the main pipeline)
   - This means code fences get Skill() transformation applied, while the main pipeline skips them

2. **Wire into `generateWorkflows()` pipeline:**
   ```
   source → rewriteWorkflowPaths → transformWorkflowCodeFences → applyPromptTransforms
   ```
   
   The order matters: `transformWorkflowCodeFences` runs BEFORE `applyPromptTransforms` so that the main pipeline's code-fence protection in `transformSkillDispatchForPi` doesn't double-process (Skill calls are already replaced).

3. **Command prompts remain unchanged** — they use the same pipeline as before, with code-fence protection.

### Edge cases

- **Skill() calls with non-gsd- prefix:** `Skill(skill="update-config")` — extend regex to match any `Skill(skill="xxx")` pattern, converting to a generic instruction like "Use the update-config skill to..."
- **Nested code fences:** GSD files use ``` for bash and pseudo-code blocks. The outer fence is the code block boundary; any inner backticks are just characters. `splitCodeFences()` handles this correctly.
- **Already-transformed content:** Idempotency — if `ask_user_question` or `subagent()` already present, don't transform again.

### Step 2: Extend Skill() regex to handle non-gsd prefix

- Current regex: `Skill\(skill="gsd-[^"]+"` — only matches gsd- prefix
- Extended regex: `Skill\(skill="[^"]+"` — matches any skill name
- For gsd- prefix: convert to Pi subagent dispatch instruction
- For other prefixes: convert to generic skill invocation instruction

### Step 3: Wire into `generateWorkflows()`

- Add `transformWorkflowCodeFences` call in pipeline after `rewriteWorkflowPaths`
- Verify command prompt pipeline remains unchanged

### Step 4: Integration verification

- Assert zero `Skill(skill=` in `generated/workflows/` output (inside AND outside code fences)
- Assert Skill() calls in command prompt code fences are still preserved (not transformed)
